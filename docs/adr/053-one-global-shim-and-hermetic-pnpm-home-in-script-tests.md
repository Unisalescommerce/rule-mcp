# 053: One global shim, and hermetic PNPM_HOME in script tests

- **Date**: 2026-09-07
- **Status**: accepted
- **Tags**: installer, cli, shim, testing, hermeticity
- **Author**: Emiliano Pisu <pisuemiliano.1980@gmail.com>

## Context

recurring session-start failure `spawn .../pnpm/bin/rule ENOENT` had a
reproducible cause: every test that shells out to `install.sh`/`uninstall.sh` spread
`process.env` into child, so developer's real `PNPM_HOME` leaked in.
`uninstall.sh` Phase 7 deletes `$PNPM_HOME/bin/rule` and `install.sh`'s
`ensure_global_shim` writes there - running installer suite silently deleted real
shim (and once repointed it at temp checkout). Separately, `package.json` declared two
bin names for same entrypoint - `rule-mcp` and `rule-mcpd` - and nothing
consumes the second: the daemon wrapper of the same name lives at `~/.local/bin/` and is
generated by service installer, independent of package bin.

## Decision

Three layers. (1) Every test that spawns shell scripts sets `env.PNPM_HOME` to a
sandbox directory, enforced by static gate (`tests/cli/script-env-hermetic.test.mjs`)
that fails any spawning test whose source does not name `PNPM_HOME`. (2) `uninstall.sh`
mirrors `install.sh`: `RULE_MCP_SKIP_GLOBAL_LINK=1` skips whole global-package
phase, and shim cleanup loops over both shim names so stale `-mcpd` shims are removed
from machines that have them. (3) `rule-mcpd` bin alias is deleted from
`package.json`; only package bin is `rule-mcp`. Claude registration on this
machine now runs `node <repo>/bin/rule-mcp.js serve` directly - no shim in spawn
path at all.

## Consequences

Positive: the installer suite ran end to end with the real shim verified byte-identical
before and after; ENOENT class is closed twice over (nothing deletes shim, and the
Claude entry no longer depends on it); one bin name means one thing to heal. Negative: a
machine that invoked `rule-mcpd` from pnpm bin must switch to `rule-mcp`
(Login Items daemon wrapper at `~/.local/bin/rule-mcpd` is unaffected).

## What would end this

Publishing to registry with real global install (`pnpm add -g`), where pnpm owns the
shim lifecycle and hand-rolled shim heal becomes redundant.

## Alternatives Considered

1. Keep both bin names for compatibility - nothing consumes alias, and every extra
   name is another shim that can go stale.
1. Fix only tests without `uninstall.sh` skip flag - leaves next
   non-sandboxed caller (another repo's suite, CI job) free to reintroduce deletion.
