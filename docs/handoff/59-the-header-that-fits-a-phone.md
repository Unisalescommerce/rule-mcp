## What this session changed

### The heading that pushed the page sideways

`3b0ad931` adds `overflow-wrap: break-word` to the headings. The Pages build failed on the responsive check with `docs/tools.html` 8px over and `docs/troubleshooting.html` 4px over at 320px. Both were headings with no break opportunity: `rule_tool_impersonation` as an `h3`, and `Troubleshooting` as an `h1`. The runner's fallback font is wider than the one this machine uses, which is why the local run passed.

`270f6330` makes the reflow test run a second pass with a wide font, so the failure is reproducible on any platform. Reverting the CSS makes that pass fail on exactly those two pages.

### The brand is the way home

`c258202d` drops the `Home` entry from the primary menu. The mark and the wordmark already link to the index, so the entry was a second door. The brand now shares the menu's face, weight and minimum height, and from 896px the brand, the menu and the preferences trigger sit on one line, with their centres within 2px.

The same commit makes the header mobile first. The breakpoints are in `rem`, so they follow the text size and not only the screen: one column under 384px, two rows from 384px, one row from 896px. Touch targets are 44px below 896px. Three layout defects came out of the new device tests and are fixed: a 40px trigger, an 8rem icon plate that could not shrink, and card grids whose `minmax(16rem, 1fr)` forced a column wider than a phone at 200% text.

### The version and the repository on the home page

`64684782` puts `v0.1.0` and a GitHub link with an inline mark at the top of the hero. The version is read from `packages/mcp/package.json` at build time, so it cannot go stale. The link opens in a new tab without an opener, like every other external link on the site.

### The contrast coverage that outlived its selector

`5e4d2223` moves the contrast check to where the elements now are: the brand link on the home page, the repository link in the hero, and the current-page pill on the chapters. The Pages build failed on `header nav a[aria-current='page'] not found` on `index.html`, because the home page no longer has a current menu entry.
